# 摄影方案复拍工作流

## 适用目标

本模式处理的是：用户看到一套喜欢的写真，希望换一位人物，像去同一家摄影店、由同一摄影团队按同一主题企划重新拍摄一组新照片。

它不是逐张换脸、原片编辑或精确复刻原机位，也不是只保留宽泛“氛围感”的普通同系列变体。当前名称是描述性工作名，不把它包装成已有行业流派。

第一版只正式支持 Codex Image 生图环境。其它模型可以复用 Prompt 思路，但没有真实回归前不得宣称完整支持。

## 输入合同

必须有：

- 一张或一组写真方案参考图；组图优先。
- 用户的生成意图；只有明确要求“生成、出图、直接生图”等动作才执行生图。

可选输入：

- 人物身份图。
- 原创女性类型。
- 图片数量；未指定时默认 5 张。
- 画幅；未指定时继承参考组的主要画幅和稳定横竖分布。
- 可选 Eagle 文件夹；只有当前环境已安装对应归档能力、Eagle 可用且用户没有拒绝归档时才使用。

用户提供单独人物图但未说明职责时，只问一次：`这张人物图是要保持同一位人物，还是只借人物气质？`

- 用户确认保持同一人物：人物图只承担身份，验收主要五官辨识度。
- 用户确认只借气质：它不承担身份，最终人物可以重新生成。
- 没有人物图：根据写真企划自动选择适配的成年原创女性类型，不从写真参考人物的脸型、眼型、痣或鼻唇关系反推；不检查组内人物一致性。

身份图里的中性表情、眼神方向、眉眼张力、闭合嘴角和静态姿势不自动属于身份。目标写真需要不同人物状态时，只保留可见且稳定的少量身份锚点，例如脸型轮廓、眼型、鼻唇关系和稳定特征痣；本张表情由目标拍摄事件接管，并在 Prompt 中明确不继承身份图的中性表情。不要把“眼神气质”与每张表情一起锁死。

## 原始输入重置合同

摄影方案复拍不是在上一张生成图上逐轮修图。首次生成和用户反馈后的每一轮重做，都必须重新建立同一组正式输入：

- 用户确认承担身份的原始人物图；没有身份图时继续使用原定的原创人物类型。
- 本张分镜被分配到的原始写真主参考，以及确有必要的同一布光子方案原始辅助参考。
- 根据原始参考、当前分镜和本轮反馈重新编译的一条完整新 Prompt。

上一轮生成图只用于诊断问题，不得自动成为下一轮视觉输入；它的放大图、裁切图、拼图或截图也一样。上一轮 Prompt 只作为追溯记录；新一轮可以保留已经确认的身份锚点、参考职责和摄影方案事实，但必须重新编译完整 Prompt，不能只在旧 Prompt 末尾追加“更粗粝、再失焦、不要太干净”等补丁式修图指令，也不能要求模型“基于上一张继续调整”。只有用户明确要求编辑某一张生成图时，才转为图片编辑任务，并明确记录该生成图的输入职责。

每轮记录必须能证明输入已重置：列出本轮实际使用的原始图片路径与职责，并写入 `generated_image_inputs: none`。新输出直接对照原始写真参考检查；上一轮输出只支持失败诊断，不能充当风格正确性的比较基准。

## 第一步：还原摄影方案

先对整组参考做可见事实拆解，不先写 Prompt，不生成综合色卡，也不把所有图片的像素统计混在一起。

### 共同写真套餐

提取多张共同支持的内容：

- 主题世界、时代与编辑气质。
- 妆容母体、发型体系、服装轮廓与主色。
- 关键场景、布景、道具和材质关系。
- 常用景别、镜头距离、构图语法与人物状态。
- 画面信息层级：主体清晰区、主导大形、次级细节、连续低细节区或留白，以及前中后景的锐度与局部微反差分配。
- 白平衡与色偏、肤色和背景色关系、黑位、高光滚降、锐度、微反差、柔化、噪点、压缩和景深。

具体动作、表情、视线、人物位置和临时道具不自动进入共同套餐。

### 布光子方案

按真实光照事件聚类，而不是按文件顺序或颜色相似度平均：

- 主光类型、面积、方向和软硬。
- 光在人脸、发丝、服装、道具与环境中的落点。
- 人物与背景的曝光差、阴影密度和环境回填方向。
- 高光面积、材质反射与景深关系。
- 高光色温、是否存在发丝或肩线边缘光、背景散景的形状与大小、局部微反差和暗角强度。

只有同一布光与曝光系统的图片才能进入同一个子方案。稳定存在两个或更多子方案时分别保留；明显不同且不能形成稳定子方案的图片作为离群图排除，并在最终摘要中用一句话说明。不能仅因两张图都明亮、都有绿色背景或都是近景就判为同一子方案。

### 新机位光照拓扑重建

“光照拓扑重建”是本工作流的描述性名称，不声称它是既有行业术语。它不是生成综合色卡，也不是要求模型复制参考图中高光在二维画面里的坐标；它要保存的是同一摄影空间中稳定的因果关系：`光源—遮挡—落点—反射—曝光`。

只要本张机位、俯仰角、镜头高度、人物朝向或动作明显不同于主参考，编译 Prompt 前必须先完成这一层。固定规则是：**机位变化不能带着光源一起旋转。** 光源、屋檐、窗洞、伞面、竹叶、墙地和环境回填先放在世界坐标中；相机只改变观看位置，人物动作改变后再重新判断哪些表面能看见光、被什么挡住、把什么颜色反射回来。

先从主参考记录一个最小拓扑，不推测不可见器材：

1. **光源**：可见或可由画面支持的天空、窗洞、门口、伞面透光、树荫散射或其它大面积来光；记录相对场景的方位、面积、软硬和色温。
2. **遮挡与调制**：屋檐、横梁、窗棂、伞、竹叶和人物自身是否挡光、筛光或形成局部透光。
3. **人物落点**：面部哪一侧、眼窝、鼻翼、下颌、肩臂、手、服装和道具分别接到主光、环境回填或阴影。
4. **环境落点与反射**：墙、地面、木构、植物和桌面如何受光，并以什么明度与颜色回填人物。
5. **曝光结果**：人物与背景的明度关系、阴影密度、高光宽度、眼神光方向、高光滚降和黑位。

再把新机位、新动作和新增道具放回同一空间，写出至少 4 条互相一致的**拓扑预测**，至少覆盖：眼神光或眼窝明暗、面部亮暗侧、肩臂／手／服装／道具中的两个落点、环境受光或反射，以及人物与背景曝光关系。预测的是新视角应当看到的物理结果，不是复制主参考高光在画面左边还是右边。

编译前逐条排除矛盾：

- 大面积阴天散射或柔和窗光不能无故变成狭窄硬边光、强轮廓光或舞台顶光。
- 俯拍只改变相机位置，不能把侧窗、门洞或水平环境光改成从镜头上方直射的暖顶光。
- 低机位位于亭廊或屋檐下时，要重新计算屋檐遮挡和开口方向；不能仅因背景面积变大就自动压成深黑商业背景。
- 伞面透光只影响伞下或伞边可接收的表面；相机升高不会把伞自动变成正上方影棚柔光箱。
- 新动作或道具若挡住原主光，必须接受对应阴影，或调整人物在场景中的位置；不能同时要求“挡光”和“原脸部落点完全不变”。

主参考因裁切、后期或光源复杂而无法支持明确拓扑时，必须标记“光源证据不足”，采用保守的大面积柔和环境光重建，只锁定画面真实支持的曝光与色彩关系；不得编造精确灯位、器材或强边缘光。

## 第二步：规划新分镜

用户指定几张就规划几张；未指定时规划 5 张。不要增加校准样张、隐藏候选或后台过量生成。

- 自动覆盖参考组的主要布光子方案，并根据参考证据组织近景、半身、全身或环境关系，不套固定景别配额。
- 用户指定画幅时全部服从；否则继承参考组的主要画幅和稳定横竖组合。
- 复用摄影方案、镜头语法和标志性拍摄类型，但重新组合人物位置、机位、动作、表情、视线和道具关系。
- 请求数量不超过 5 张时，最多 1 张允许近似复拍标志性画面；超过 5 张时整组最多 2 张。其余图片不得照抄参考图的完整构图、动作与视线。
- 默认避开身体背向镜头却扭头回看的高风险动作，保持头肩方向自然。
- 每张新分镜完成后立即执行光照拓扑重建；若新机位与当前布光无法同时成立，优先调整用户没有明确锁定的人物站位、朝向、动作或机位，不把参考光场改成更常见的商业布光。用户已经明确指定机位时保持机位，改用人物站位、朝向、动作或道具遮挡来解决冲突。

没有人物身份图时，“好看优先”只作用于原创人物、妆面呈现、动作和构图选择；不得为了更漂亮而换成参考组不存在的商业布光、调色、妆造或成像系统。

### 人物事件与表情因果

“人物事件与表情因果”是本工作流的描述性检查名，不声称它是既有行业术语。身份图回答“是谁”，不能同时把身份图里的中性表情冻结到所有新分镜；每张新分镜先确定一个当前场景真实支持的具体事件，再编译表情与身体响应。

按以下因果链规划：`现场触发 → 身体即时反射 → 眼睛／眉毛／下眼睑／双颊／嘴唇或嘴角的可见变化 → 视线与手部继续追随事件`。例如雨滴、移动光斑、风吹发丝、叶片或道具接触只有在当前场景真实存在时才可使用；不要为了制造活泼感凭空增加不属于企划的事件。

- 不只写“自然、灵动、安静好奇、惊喜、微笑”等情绪标签；这些词没有说明表情为什么发生。
- 安静场景可以只出现轻微眉眼变化、呼吸、视线转移或未完全形成的单侧笑意；门禁检查的是因果成立，不要求每张大笑。
- 近景用眉眼、鼻翼、双颊、嘴唇和呼吸的小变化；全身或环境照还要让头肩、重心、手臂与步态响应同一事件。
- 动作、视线和表情若来自三个无关任务，即使每个局部都好看，也必须重构分镜。

### 背景信息层级

“背景信息层级”同样是描述性检查名。它不是强制所有写真极简或大虚化，而是重建参考图里“什么最清楚、什么只作为大形、哪里低细节、哪里让主体呼吸”的组织方式。

先从参考组提取：主导背景形状的数量与尺度、主体周围是否存在连续低细节区、次级物体能否被逐一辨认、背景锐度与局部微反差、前中后景的清晰度衰减。再按参考证据写进每张 Prompt：

- 参考若依赖大型叶面、墙面、窗洞、天空或深色阴影形成大色块，就保持这些主导大形，并把次级枝叶、纹理和远景物体合并成低反差、低锐度色块；不要同时要求每层背景、每片叶脉和每根枝条清楚。
- 参考若本身是繁密装饰、城市信息流或高细节环境，可以保留密度，但仍要说明主体清晰区、次级层级和视觉落点，不能让所有细节拥有同等对比与锐度。
- “背景比人物暗”不能代替信息层级；暗背景仍可能因高锐度、高微反差和密集高光而显得繁杂。
- 景深、锐度和微反差必须分区描述：主体可以清晰，背景不必同步使用同一锐度与局部反差。

### 去商业抛光层

只有原作本身依赖欠曝、失焦、堵塞暗部、截断高光、手持晃动、旧数码压缩或偶发构图时，才启用这一层。它不是把所有写真统一做脏，也不是在 Prompt 末尾堆“粗粝、低清、复古”等抽象词；精致 editorial、稳定棚拍或材质展示型原作应保留其清晰度和塑形。

先审计模型最容易自行补入、但原作没有支持的商业摄影升级：连续暖色发丝轮廓光、沿肩线完整发亮、皮革折面被逐条塑形、稳定清楚的双眼与脸部焦点、无来源正面回填、奶油背景、英雄式低机位和过度完整的姿态。确认原作确实缺席后，把它们改写为正向物理结果：

- 为天空或亮部曝光，让人物脸、服装和木构自然压成大块暗形；亮部可以直接截断，暗部不必保留完整材质信息。
- 高光只落在原作支持的鼻尖、唇缘、指节、栏杆上沿或零碎发丝，不沿头发、肩线和整件外套形成连续漂亮轮廓。
- 焦点可以落在前方栏杆、飞动发丝或邻近物体，允许脸和衣领自然脱焦；不要一边要求失焦，一边又锁定清晰双眼与皮肤纹理。
- 服装若在原作中主要作为黑色大形，就写成哑暗、吞光、局部无细节，不要求皮革折面、缝线和反射被完整展示。
- 原作若像仓促抓拍，可使用轻微歪斜、非完整裁切、重心正在变化和短促手持晃动；不要把低机位自动组织成英雄式时装广告。

这层每次只压制当前输出实际出现的 1–3 个商业升级，不把所有降质信号同时塞满。用户已经说“只差一点”时，保留已成立的构图、人物事件和光照拓扑，只重新编译完整 Prompt 中的成像与抛光关系；仍遵守原始输入重置合同。

## 第三步：给每张图分配参考职责

整组参考负责分析，但每张正式生成只使用：

- 1 张主参考：决定本张布光、曝光、色彩和成像质感。
- 最多 2 张辅助参考：只在主参考缺少本张必需的妆造、场景或材质证据时补充同一布光子方案信息。
- 可选 1 张人物身份图：只在用户确认保持同一人物时使用。

辅助参考不是配额；主参考已经足够时只用主参考。主参考和辅助参考必须来自同一布光子方案，辅助图不能改变主参考的光向、高光色温、人物与背景曝光差、反差、暗角或散景。无法证明辅助图只补充必要信息时就排除。不要把明亮伞下近景、暗亭逆光和阴天环境照同时输入同一张生成任务。不要把上一张生成图自动作为下一张输入。

正式 Prompt 先按图片顺序分配职责：

```text
图片 1 是人物身份参考，只负责保持同一位成年人物的主要五官辨识度，不负责妆造、姿势、场景、构图、光线或调色。
图片 2 是本张主摄影参考，负责布光、人物与背景曝光关系、色彩和成像质感，不承担人物身份。
图片 3–4 是同一布光子方案的辅助摄影参考，只补充写真套餐、场景、服装材质与系列关系，不承担人物身份。
```

没有人物身份图时，从“图片 1 是本张主摄影参考”开始编号。实际只有几张图就写几张，不保留不存在的编号。

## 第四步：编译正式 Prompt

每张 Prompt 必须包含以下职责，但最终写成一段连续、紧凑的中文拍摄指令，不显示内部模块标题：

1. 参考图片职责。
2. 共同写真套餐。
3. 本张构图、机位、人物事件与表情因果，以及标志性复拍边界。
4. 人物身份或原创人物类型。
5. 妆容、发型、服装、饰品和主道具。
6. 场景、空间层次与背景信息层级：主导大形、次级细节、主体清晰区、低细节区或留白，以及分区景深与微反差。
7. 当前布光子方案与新机位光照拓扑：世界空间中的光源、遮挡、人物和环境落点、反射、人物与背景曝光关系，以及新视角应看到的拓扑预测。
8. 成像系统：白平衡、色偏、反差、黑位、高光、锐度、微反差、柔化、噪点、压缩和景深。
9. 紧凑质量防线；只有用户明确要求时，才加入用户指定的署名文字。

编译时按以下优先级组织高信号信息：参考职责与主参考优先级 → 身份与表情分控 → 新分镜及人物事件 → 背景信息层级 → 主光来源、方向、落点与人物／环境曝光关系 → 色彩和成像质感 → 必要质量防线 → 用户明确要求的可选署名。不要在每张 Prompt 中重述整套分析，只保留本张真实可见且会影响结果的套餐元素。默认不添加任何署名或水印，也不得自行写入 `nuyoah`。

机位明显变化时，正式 Prompt 必须用紧凑自然语言明确三件事：

1. **世界空间不变量**：主光相对场景的方向、面积、软硬与色温，主要遮挡物和环境回填保持不变。
2. **新视角可见结果**：面部、眼神光、手臂、服装／道具、环境与背景曝光中至少 4 个相互支持的落点结果。
3. **相机边界**：新机位只改变观看关系，不把光源跟随镜头旋转，也不自动升级成顶光、硬轮廓光或高反差商业人像。

先写正向的物理关系，再补 1–3 个具体禁止项。不能只写“保持相同光影”“复制参考图光线”或堆禁止词，这些句子没有说明新机位下光为何落在那里。

主参考没有出现的商业摄影升级必须按图写成 1–3 个具体禁止项，例如暖色发丝轮廓光、圆形奶油散景、电影化重暗角、现代商业磨皮或过强数字锐化。只写当前主参考确实缺席、且模型容易自行补入的项目；不要堆通用负面词。辅助参考不得覆盖这条边界。

无人物身份图时必须写入并替换变量：

```text
本张重新生成一位「【原创女性类型】」类型的成年原创女性，不要继承写真参考图中人物的脸。
```

有身份图时改为：

```text
人物身份只来自图片 1，保持她的主要五官辨识度；写真参考图中的人物不承担身份，不能覆盖人物身份图。
```

若本张表情不同于身份图，继续补充：

```text
只保留图片 1 中可见且稳定的少量身份锚点；不要继承其中性表情、眼神方向和嘴角状态。本张眉眼、呼吸、嘴唇、视线与身体反应全部服从【当前人物事件】。
```

不要把“摄影质感”缩写成复古、电影感或旧数码。必须写出可见证据；没有证据的器材型号、胶片型号、摄影师或后期流程不得编造。

## 第五步：生成次数与失败处理

- 每个锁定 Prompt 只提交一次。用户要求 N 张就执行 N 次真实生图提交；未指定时执行 5 次。
- 不生成校准图，不在后台多生成候选，不因画面不够好而自动补图。
- 接口报错、安全拦截、超时或无图输出也占用本次提交次数。保存原 Prompt、编号、错误和 request ID（若有），不改词、不自动重试，然后继续尚未提交的其它编号。
- 有真实图片但视觉检查未通过时，仍记录为 `test` 或 `failed`，明确问题；只有用户明确要求修第几张时，才为对应编号创建下一轮 Prompt 和新资产。
- 用户要求重做时，先回到原始输入重置合同：重新读取原始人物图与本张原始写真参考，从摄影方案和失败诊断重新编译完整 Prompt，再做一次新的文生图／参考图生图提交；不得把待修的生成图送回模型继续编辑。

## 第六步：逐张检查

四个摄影方案轴都直接对照本张原始写真参考检查，不能使用综合色彩分数掩盖单项失败，也不能用“比上一轮改善”代替绝对相似度：

1. **写真套餐**：场景、妆发、服装与关键道具是否属于同一企划。
2. **布光曝光**：是否服从分配的布光子方案；世界空间中的光源、遮挡与环境反射是否在换机位后保持稳定；输出是否兑现本张拓扑预测；人物和环境是否处在同一曝光系统。任一关键拓扑关系自相矛盾，即使画面好看也判本轴不通过。
3. **色彩关系**：肤色、背景色、黑位、高光滚降及人物与背景的明度关系是否属于参考组。
4. **成像质感**：锐度、微反差、柔化、噪点、压缩和景深是否属于同一系统；原作偏粗粝时，再检查是否被连续暖色轮廓光、稳定脸部焦点、皮革塑形、正面回填或英雄式构图重新商业化。

四轴之外，再独立检查三个用户感知门禁：

5. **人物事件与表情**：表情是否有当前画面可见的触发原因；眉眼、呼吸、嘴角、视线、手部和身体是否响应同一事件。只有正确脸和正确视线、但面部仍像中性身份照，不能判为通过。
6. **画面信息层级**：主体清晰区、主导大形、次级细节、低细节区或留白是否服从参考组；不能因背景曝光较暗，就忽略密集枝叶、高锐度、高微反差或高光碎点对主体的争夺。
7. **原作绝对保真**：不看上一轮时，本张是否仍能在写真套餐、布光曝光、色彩、成像质感和画面层级上被判断为来自同一摄影企划。相对上一轮更粗糙、更失焦或更有风格，只能记录为相对改善；原作绝对保真未通过时继续标为 `test`，用户明确认可后再单独记录用户验收。

任一门禁不通过时，即使身份、人体和光照正确，也不得标记为 `adopted` 或 `final`；按真实问题保留为 `test` 或 `failed`。

同时检查脸、五官、手指、手臂、腿脚、身体连接、透视、服装核心要求、构图和文字。有人物身份图时检查主要五官辨识度；没有人物身份图时不检查组内同脸。

不要逐一比较生成脸与写真参考人物，不增加“身份泄漏”验收层。直接输入原始参考图加文字约束只能降低继承参考脸的倾向，不能宣称技术性保证完全不吸收。

## 第七步：用户输出与可选 Eagle 归档

核心交付必须直接出现在当前对话中，不得依赖 Eagle、本地知识库或另一个未随包提供的 Skill。按编号交付：

1. 一段简短摄影方案摘要。
2. 实际图片；API 无图时给出对应编号、错误和 request ID（若有）。
3. 每张实际使用的完整 Prompt。
4. 原始参考图及人物身份图的职责；重做轮次同时记录原始输入路径、`generated_image_inputs: none` 和本轮编号。
5. 每张质量状态（`test`、`failed`，或用户确认后的 `final`）及具体通过项／问题。
6. 一条可复制的追溯记录，把上述事实绑定到同一编号；如果没有可写的项目记录位置，就以对话中的结构化文本作为正式追溯记录。

完成核心交付后，才检测可选 Eagle 集成。只有同时满足以下条件才归档：当前环境可以调用 `nuyoah-codex-image-to-eagle`、Eagle 已连接且可写、用户没有拒绝归档。用户给出 Eagle 文件夹链接或 ID 时优先使用；否则遵循当前项目真实存在的默认目录，不猜测目录。

归档成功时同步并回读：

- 中文主题加单张内容说明作为 item name。
- 注释保存实际完整 Prompt、正式输入的参考图职责、质量判断和追溯记录。
- 重做轮次额外记录原始输入路径、`generated_image_inputs: none` 和本轮编号，证明没有把上一轮生成图作为输入。
- 未经用户确认默认不得标为 `final`；明显问题使用 `test` 或 `failed`。
- API 无图失败只写失败记录，不创建伪 Eagle 项目。

归档成功时在对应编号后附 Eagle ID。未安装、未连接、不可写、同步失败或用户不使用 Eagle 时，简短说明“未归档到 Eagle”，保留对话中的完整追溯记录并结束任务；不得因此删减 Prompt、质量结果或图片，也不得把任务标为失败。除非用户要求，不在对话中展开全部内部拆解和分镜矩阵。
